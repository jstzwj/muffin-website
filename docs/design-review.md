# 页面调整与检查

本次使用 [Taste Skill 2.5](https://github.com/Leonxlnx/taste-skill)，安装在 `C:/Users/jstzw/.codex/skills/design-taste-frontend`。页面类型为 software，设计组合见 [design-plan.md](design-plan.md)。原始布局、系统与交互资源均与安装包逐文件校验一致。

## 页面内容

- 首屏直接说明“原生桌面 Markdown 编辑器”，列出 C++、Qt 6 与支持的系统。
- 使用 Muffin 应用真实截图。首屏展示编辑视图，下一屏默认展示源码；访客可以切换编辑视图、源码与 Night 主题。
- 代码、表格、Mermaid 与 LaTeX 图片来自同一份公开示例文档 `public/muffin-notes.md`。
- 功能与导出说明以 Muffin 的 README 为依据。没有虚构用户、评价、性能数字或价格。
- 保留中英切换、语言记忆、Windows x64/ARM64 下载，以及 GitHub 发布信息更新和离线回退。
- 采用原始 Logo；没有占位素材、待替换图片或需要补充的商业资料。

## 检查方法

浏览器检查使用 skill 自带的 consistency、layout、shoot 和 perf 脚本，逐个运行，各自使用独立的无头 Chrome。检查宽度为 1440、1024、820、768 与 390；layout 保留标题压力测试。生产 CSP 另由 Playwright 功能测试验证。

完整 consistency 检查后修正了问答栏的列间距、重复截图与次要按钮对比度；随后对最终构建运行了五种宽度的 quick 复查。复查有 8 个 FAIL 和 32 个 WARN，并非零告警。原始报告、裁剪图和浏览器配置保存在忽略提交的 `.taste-skill/`。

手机首屏的源码链接居中后，另做了 390 宽度截图与 quick 复查（包含该宽度的 rhythm 规则）：7 个 FAIL、13 个 WARN，FAIL 仍全部来自居中首屏和纯文字 FAQ，理由如下。

## 保留的检查例外

| 规则                                          | 判断与依据                                                                                                                                                       |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `text-only`                                   | 五种宽度都将常见问题区标为纯文字。这里保留四个完整答案，配图不会增加信息，不为消除告警插入装饰。                                                                 |
| `container-edges`                             | 标记居中的首屏标题、平台说明。页面使用 skill 实际抽取的 `hero--centred`，居中是该布局的预期行为；外层容器和图片两侧边距相等。                                    |
| `container-edges` / `one-section`（完整检查） | 将原始 `btn--xl` 在平板上的 640px 宽度视为未对齐，或将大按钮视为文字色块。保留 skill 的按钮规格，实际下载链接和点击区域正常。                                    |
| `hero-lines`（layout 压力测试）               | 脚本给中文标题追加正文至约 35 个字符后，1440 与 390 下变成四行。发布文案在五种宽度均为两行；没有承诺支持自动替换成更长标题。未修改脚本、标题字数上限或字体规格。 |
| `copy-headline` / `copy-buttons`              | 按英文空格与动词表判断中文，未识别“下载”这个动词。中文标题直接写出类别，按钮明确说明动作和对象。                                                                 |
| `links` / `nav-labels`                        | 下载区位于真实的 `footer#download`，Logo 回到首屏，功能菜单指向对应内容。锚点和手机导航经过功能测试。                                                            |
| `section-gaps`                                | 原始系统的上下留白、居中首屏和问答行内容密度不同，脚本认为节奏不一致。保留一屏一节和同一套间距 token。                                                           |
| `font-load`                                   | 原始字体组合声明 IBM Plex Mono，但页面没有使用等宽字体的网页文本。实际使用的 Familjen Grotesk 两个字重均为本地字体；无需额外下载未使用字体。                     |
| `nav` / `nav-current`                         | 平板菜单按钮保留原始内边距；导航不根据滚动自动切换当前栏目。菜单、锚点和固定导航均可使用。                                                                       |
| `assets`                                      | 高频自动审查时 GitHub 发布 API 返回过 403，页面继续使用随构建附带的发行版链接。限流、离线回退及新版本更新均有独立功能测试。                                      |

页面不使用自动 shader、滚动场景或光标追光。此处优先回应用户对文案和页面观感的反馈；交互集中在查看产品界面与选择下载包。

## 功能与性能

生产构建和 8 项 Playwright 测试通过。除语言记忆、图片切换、下载架构、新发行版与无效下载链接外，还验证英文下载区在 iPhone 13 的实际可用视口（390×664）下没有内容重叠。手机底部允许随内容增长，在 390×844 下保持一屏。

手机截图采用约 2 倍显示宽度的 WebP 文件，功能图片通过 `srcset` 选择尺寸。性能复查没有 FAIL；4 条 WARN 分别为两个视口中的小尺寸 Logo 未延迟加载、主机 CPU 繁忙。传输量约 303 KiB（桌面），没有损坏请求或布局偏移；繁忙主机上的加载时间仅作本地参考。正式结果在本地 `.taste-skill/perf-shipped.json`。
