# 页面调整与检查

本轮使用已安装的 [Taste Skill 2.5](https://github.com/Leonxlnx/taste-skill)，按用户提供的实际 Muffin 编辑、源码和左右分栏截图校正网页窗口。版式与内容安排见 [design-plan.md](design-plan.md)，组件维护和性能证据见 [product-demo.md](product-demo.md)。

## 本轮变化

- 按实图重建应用菜单、文件/大纲标签、文件树工具栏、22.7% 侧栏、README 居中 Logo、竖排徽章与状态栏；仅标题栏保留 macOS 控件。
- 正文引入项目 GitHub 主题中相同的 Open Sans 字体与许可。英文 README 开头衔接表格和代码示例；Night 切换改变整套窗口配色。
- 源码增加逻辑行号、自动换行、当前行底色与真实主题的标题/强调/链接颜色。左右分栏使用等宽的源码和只读预览面板，保留标题、锁定与链接图标；链接按钮可以开关双向同步滚动。对应内容锚点支持长行换行和模式切换后的阅读位置保持。
- 按后续截图纠正底部圆形按钮的含义：三个按钮分别选择编辑、源码和分栏模式。它不是侧栏折叠按钮。
- 表格、代码和主题使用 HTML/CSS，流程图使用 SVG，公式使用原生 MathML。主视觉与功能展示不再依赖产品截图，也没有引入新的运行时依赖。
- 保留官网白底、浅绿展示、窄幅介绍和自然内容高度。桌面和手机默认显示文件树，手机在分栏模式暂时隐藏文件树以留出面板宽度，其他模式恢复；功能细节仍为手机单列。
- 将 1 GiB 混合 Markdown、原生 C++/Qt、按需排版和增量更新放到首屏与独立优势区，并链接项目的原始测试记录。
- 数字是文档规模，不是秒开时间。既有测试环境为 Windows，不将独立 Core 阶段结果当成 Mac GUI 性能；实际打开时间与内存仍取决于设备和内容。
- 旧截图已移入本地忽略提交的归档，不再随构建部署。分享 PNG 也使用本轮 HTML 窗口裁切生成，不再独立绘制另一套界面。

## 功能验证

构建与桌面/手机共 **14 项 Playwright 测试通过**。验证源码逻辑行与配色、左右面板的尺寸和位置、同步/独立滚动、重新开启同步、反向滚动及模式切换后的阅读位置；保留侧栏标签方向键切换、目录跳转、底部三个模式按钮、菜单顺序、默认文件树、README 和编码状态验证。同时覆盖生产 CSP、Night 配色、SVG/MathML、大文件信息、零产品截图请求、中英切换与记忆、双语文档链接、FAQ、下载菜单键盘操作与架构选择、发行版更新及离线回退。

## 浏览器检查

使用 skill 原始 consistency、layout、shoot 和 perf 脚本，逐个运行，每个使用独立无头 Chrome。覆盖 1440、1024、820、768、390 五种宽度，并查看对应截图。自定义窗口与自然高度版式不使用 skill 的预设 hero 类；默认 layout 检查保持开启，但不会对该标题自动做预设 hero 长度替换。

本轮报告保存在 `.taste-skill/source-split/`，此前版本报告保存在 `.taste-skill/faithful-window/` 和 `.taste-skill/html-demo/`。源码和分栏截图使用构建页面的本地模式预设副本；实际按钮切换和滚动由上述测试直接验证。这些临时副本不参与发布。参考版式保留以下与工具默认规则不同的选择，不以改写检查器或隐藏内容清除：

本轮五种宽度的 quick consistency 汇总为 **120 FAIL、164 WARN**，各宽度的页面运行错误均为空，与前一版汇总一致。该报告并非全部通过；以下区分滚动窗口带来的识别误差与为还原实图而保留的样式：

- `overlap-text` 将窗口滚动视口之外、实际已裁切的文档文字与状态栏或后续区块比较。报告裁切图中对应文字并未绘制，状态栏、切换按钮和后续内容没有实际叠字。
- `text-contrast` 包含实际对比度不足：为还原项目 GitHub 主题，窗口链接保留 `#4183c4`，白底对比度约 3.99:1；Qt 和平台徽章的白字绿底约 2.56:1、3.5:1，均低于普通正文的 4.5:1。另一些结果将已裁切文字与窗口外的浅绿背景比较，属于识别误差。本轮保留真实主题和徽章颜色，未将这些结果记作通过。
- `no-visual` 未将自定义 HTML 窗口、表格和 MathML 计入图片覆盖率。五种宽度中这些内容均实际可见；用户明确要求代码组件，不补回位图来满足图片比例。
- `heading-scale` 同时比较了网页与模拟文档中的标题。文档排版保留自己的层级，网页 FAQ 仍采用小号分隔标签。
- 手机 `cut-text` 对应文件树的长文件名与底部条目；文件名使用省略号，列表可在自己的视口内滚动，未造成网页横向溢出。
- 手机 `right-edge` 的 8px 差异来自展示区的 16px 边距与正文的 24px 边距，左右均对称。

| 规则                                       | 保留依据                                                                 |
| ------------------------------------------ | ------------------------------------------------------------------------ |
| 整屏高度、一个屏幕只出现一节及相邻区块检查 | 按参考使用连续阅读和自然内容高度，不增加无用的内容或空白凑足屏幕。       |
| 统一容器边缘、左右分栏与网格               | 简介、正文和产品展示各有左右对称的宽度；功能区左图右文，下载区居中。     |
| 首屏品牌标题、中文动词和标题字号           | 首屏品牌下一行明确说明类别；中英文案都有具体动作。FAQ 使用小号分隔标题。 |
| 纯文字 FAQ 与下载区                        | 内容和操作足够说明用途，不额外添加无信息作用的图片。                     |
| 浅灰次要按钮、图片说明和摄影数量           | 清晰深色文字搭配浅灰按钮；用户明确要求代码展示，软件页面不添加无关照片。 |
| 大文件的数字图示                           | 字节、行数和文件大小来自实际测试文档；不代表网页本身加载了 1 GiB 文件。  |

性能数据来自本地构建，只作资源体积和浏览器工作量参考，不代表 Cloudflare 线上网络条件。最终域名的 canonical、sitemap 与绝对分享图地址仍按 README 部署说明配置。

本轮 perf 为 **0 FAIL、2 WARN**。含 Open Sans 字体及发行版请求，桌面总传输量约 199.7 KiB，手机约 198 KiB；没有失败请求，布局偏移为 0。两项警告来自同一矢量 Logo 在两个位置的原始尺寸大于显示尺寸，页面图片总传输量不足 2 KiB，未为此生成额外位图。此前报告继续保留，发行版离线回退由功能测试覆盖。

编辑、源码、分栏三种模式均已对照用户截图查看 1440、1024、820、768、390 五种宽度的效果；手机分栏的两个面板保持可读宽度，页面没有横向溢出。开发服务器返回 HTTP 200，当前页面包含实际布局的 HTML 窗口和 1 GiB 介绍，不含 `/screens/` 引用。
